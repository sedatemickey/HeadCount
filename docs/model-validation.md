## 需要准备

- 当前已内置 medium 并核对上游固定提交的 SHA256；但模型卡 MIT 与 ONNX AGPL-3.0 声明不一致，授权澄清仍待完成，见 `models/NOTICE.md`。
- 20～50 张获授权的代表性教室/班级合照，不需要姓名和身份信息。
- 遮挡、多排、小头部、暗光、侧脸、背景海报等样例。
- 人工完整标注的头部框，不能只提供照片总人数。

建议先准备少量样本筛选候选，再将验证集与最终测试集分开。只有同一批固定照片、硬件、输入尺寸和匹配规则下的结果才适合横向比较。

## 标注格式

建立本地 `datasets/classroom/dataset.json`：

```json
{
  "images": [
    {
      "file": "images/photo01.jpg",
      "heads": [
        [0.10, 0.12, 0.15, 0.20],
        [0.22, 0.13, 0.27, 0.21]
      ]
    }
  ]
}
```

每个框是 `[xmin, ymin, xmax, ymax]`，范围 0～1，基于 **EXIF 方向校正后的整张图**。`heads: []` 可表示负样本。图片相对路径不能越过评测集目录。

## 执行

先执行模型 doctor；预热不计入逐张推理延迟。项目根目录运行：

```powershell
.\backend\.venv\Scripts\python.exe -m app.evaluate `
  datasets/classroom/dataset.json --mode standard --output reports/standard.json

.\backend\.venv\Scripts\python.exe -m app.evaluate `
  datasets/classroom/dataset.json --mode fine --output reports/fine.json
```

输出包括：

- IoU ≥ 0.5 的一对一最大匹配后的 precision / recall。
- 每张照片的误检 FP、漏检 FN；重复框通常表现为 FP，需人工复核原因。
- 总人数绝对误差与 MAE（不能代替定位指标）。
- 推理均值、P95，以及模型、执行后端、阈值和输入尺寸。

耗时范围为推理适配流程（读入方向已校正图、切片、前后处理和模型推理），不含上传、网络、数据库和浏览器渲染。记录 CPU 型号、内存和软件版本；短数据集的 P95 仅供参考。

工具报告不包含真实图片或姓名，但可能包含文件名和模型配置，仍默认不入 Git。界面手动添加当前仅有点坐标，不能直接替代本评测工具所需的完整头部框真值。
